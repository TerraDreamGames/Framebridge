# Optional native advanced controls

Choose **Interactions → Custom settings → Advanced control** in Figma's Properties inspector. Configure one optional control per native layer. Styling stays in Figma and native Roblox Properties. The browser preview shows appearance; behavior executes in Roblox Play. Progress bars, toggles, sliders, cooldowns, tooltips, draggable windows, skill trees and roulette use the existing trusted interaction runtime. Existing panel actions, tab groups and live text supply window open/close, tabs and text data bindings.

| Control | Configuration and native behavior | Outputs for local game scripts |
| --- | --- | --- |
| Progress | Numeric min/max/value, direction and Fill child; scales authored fill Size along its chosen axis, clamped to the range | `FramebridgeValue`, `FramebridgeControlStatus` |
| Toggle | Button, initial boolean; native Activated toggles and selected-state visuals follow the value | `FramebridgeValue`, `FramebridgeSelected` |
| Slider | Button track, range, step, optional Fill/Thumb direct children; mouse/touch drag, selected keyboard/D-pad arrows along the track axis and activation adjust the bounded value | `FramebridgeValue`, `FramebridgeSelected` is not modified |
| Cooldown | Button, .05–3600 seconds, optional Fill; activation starts countdown and gates further activations, including the existing panel action | `FramebridgeCooldownRemaining`, `FramebridgeCooldownReady` |
| Tooltip | Button owner, separate panel and 0–5 second delay; mouse hover/selection opens, touch taps toggle; passive leave/deselection, cancel and hidden owner close | `FramebridgeTooltipVisible` |
| Window | Native container, optional descendant drag handle, parent bounds setting; mouse/touch drag changes native Position | Native `Position` |
| Skill tree | Buttons, initial unlocked state, up to 16 prerequisite skill IDs; unlock available skills, reject locked/unlocked activation and propagate resets | `FramebridgeUnlocked`, `FramebridgeSkillStatus` (`Locked`, `Available`, `Unlocked`), `FramebridgeSelected` |
| Roulette | Button, 2–64 display strings up to 128 characters and .1–30 second spin; one spin at a time with bounded animated selection and completion | `FramebridgeRouletteStatus`, `FramebridgeRouletteIndex` (1 based), `FramebridgeRoulettePreview`, `FramebridgeRouletteValue` (only complete result) |

Use **More options → Create control examples** to add one editable Figma scene with all eight control kinds (nine control owners), tabs and a live Coins label. The example retains native frames and text, contrasting fill artwork and real links between controls. It creates a new page, or a separate section when the Starter page limit is reached. Existing content and settings are retained; failed creation rolls back the new content. Repeating creation gives each scene independent links.

For skill controls, prerequisite checkboxes show the selected count and allow mouse or keyboard selection without modifier keys. Up to 16 prerequisites can be selected; existing selections remain removable at the limit. A missing stored skill is shown explicitly so its reference can be removed. These edits use the same plugin Undo/Redo history as other control settings.

Local `FramebridgeValue` and `FramebridgeUnlocked` attributes persist across runtime rebuilds and can be supplied by game scripts. Toggle and skill selected attributes work with existing state artwork placed inside those buttons. Controls themselves cannot also be state artwork or motion owners; cooldown is the only control that can also carry a panel action. This explicit boundary prevents multiple runtime writers from fighting over geometry or activation.

For numeric/boolean controls, **Value source** can read a simple LocalPlayer attribute or leaderstats value. Bound controls are read only: no activation or controller setter writes back to the player. Attribute updates and late creation, replacement, change and removal of leaderstats are event-driven. Missing/invalid data sets `FramebridgeControlStatus` to `Missing data` and retains the last displayed value; successful player reads set `Bound`, local reads set `Ready`. Supported leaderstats controls use IntValue, NumberValue or BoolValue. Existing live labels separately support strings and escaped templates.

Value and leaderstats-container renames also refresh bindings, including previously unmatched children renamed into the expected names. Name observation is capped at 1,024 direct children on the player and leaderstats container. Overflow sets `Missing data` and emits a diagnostic; observation resumes after the topology returns within the ceiling. Controls retain their last display while missing and restore their owned design properties on disposal.

The generated runtime supplies local UI state only. Your game server authorizes skill progression, currency, rewards and roulette odds. The roulette output is a local visual demonstration, never an authoritative reward or server request. Packages cannot contain executable expressions, event code, remotes or arbitrary paths.

Artwork targets are stable identities within the same screen. Fill/thumb must be direct GUI children with no list/grid, automatic-size, aspect, size-constraint or flex ownership; slider tracks cannot use automatic size; authored full fill Size is the maximum size. A thumb travels from 0 to 1 along the track; set its AnchorPoint in Properties to center it. Tooltip panels cannot contain their owner or also carry controls/motion, be tabs or be action targets. Skill graphs reject self references and cycles. Shared target ownership, missing/ambiguous targets and rasterized interactive hierarchies block export/import. Windows require unrotated ancestors and cannot be owned by a parent list/grid. Drag bounds use the parent's current padded content rectangle. For ScrollingFrame, that canvas content is intersected with the visible viewport excluding scroll gutters; direct screen children use the current native collector dimensions. Resize, scroll and UIScale are re-read during a drag; a competing Position.Scale edit invalidates its stale baseline. Integral offsets can leave less than one logical pixel of margin. Physical device, world-projected input and Play safe-inset acceptance remain separate gates.

Touch tooltip taps own their open/closed state independently of hover and selection. Incidental hover/selection changes cannot cancel the first tap or reopen the second tap's dismissal. Native mouse movement or keyboard/gamepad input returns ownership to normal hover/selection; explicit `focusTooltip`, focus cancellation, or a disabled/hidden owner clears the tap state. Opening still respects the configured delay. These runtime rules do not establish native touch presentation or emulator event ordering.

The runtime uses one time connection per screen containing timed controls and bounded input/data subscriptions. Destroy disconnects all subscriptions, cancels drags/spins/countdowns/tooltips and restores owned native properties. External native property changes are remembered so teardown/rebuild preserves edits. Numeric time steps cap at .25 seconds; there are no spawned countdown or roulette loops. `connectionCount`, `stepControls`, `setControlValue`, `setSliderRatio`, `focusTooltip` and `moveWindow` provide inspectable controller methods for tests or locally mounted source components. These methods validate bounds and bound-data guards; input methods also honor disabled controls.

Transfer validation, source formats and .rbxmx all carry the same data and trusted runtime. Updates retain matched native controls, listeners and user scripts. Edited generated scripts block changes before mutation. All source renderers use the existing mount/cleanup integration; roblox-ts receives the existing sibling FramebridgeInteractions module requirement. Models embed the trusted LocalScript. No additional framework or engine is required.
