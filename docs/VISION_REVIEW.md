# Optional AI structure review

After Analyze, open **More options → Review structure → Optional AI structure review** in the hosted private build. Local structure review remains available. AI is disabled in the service by default, and the session checkbox starts unchecked. Sign in through **Images → Roblox sign-in**, enable the session, and **Check AI service**. This check authenticates with the private service without calling an AI provider.

Choose one analyzed screen or a focused region using source-screen percentages. **Preview shared data** crops and re-encodes the existing source screenshot locally. It shows the exact image and projected metadata before any provider request. Metadata contains temporary layer labels, names, source types, exported classes, transformed bounds relative to the cropped image, parent labels, editability and compatible classes. Up to 120 characters of text per layer can be included separately. Turning text metadata off does not remove visible text from the screenshot. Hidden layers and metadata outside the region are excluded; an intersecting parent can still appear with bounds extending outside the crop. Source IDs and label mappings remain only in plugin memory.

Approve sharing the displayed screenshot and metadata with the private service and OpenAI, and choose a maximum USD allowance. Consent resets when the screen, region, text option, account or analyzed source changes, and after each request. **Request AI review** requires valid consent and an allowance at least as large as the configured reservation. No automatic AI requests or paid retries run. Closing the pane turns AI off and cancels pending work.

Suggestions cover names, compatible native classes, scroll axes, measured lists/grids, panel/tab-group roles, button-state artwork and repeated component candidates. Confidence is the provider's assessment, not measured accuracy or proof of native behavior. **Apply reviewed correction** rechecks the current compatible layer and uses normal configuration and Undo history. List/grid corrections use existing measured geometry checks. State artwork must be a separate editable layer beneath a native button, with one artwork layer per state and no competing control or motion writer. **Review component candidates** opens the existing component exporter, which verifies local equivalence and requires explicit extraction/download. AI cannot provide scripts, expressions, arbitrary property changes, remote resources or ready-made packages.

**Undo reviewed correction** and local **Undo correction** use shared layer history. They remain available after accepted changes discard obsolete results or mark analysis stale; active work/transfer and an empty history disable them. Exports contain only accepted ordinary overrides and the existing trusted runtime. Provider settings, keys, consent, requests, label maps, confidence, reasons and quotas are excluded. AI settings/results use session memory; no design plugin data or preference-sync records are written. Changed source discards obsolete results. Local review remains usable when AI is disabled, unavailable, cancelled, refused, malformed or over quota.

## Provider and privacy

The fixed OpenAI Responses endpoint receives one base64 PNG with low image detail, a closed JSON schema, bounded output tokens and `store:false`. Files, external image URLs, tools, background jobs and conversation continuation are excluded. The model, key and prices are server configuration; clients cannot choose an endpoint, model, key or prompt. Redirect responses are rejected without following them. See official OpenAI documentation for [image inputs](https://developers.openai.com/api/docs/guides/images-vision) and [structured output](https://developers.openai.com/api/docs/guides/structured-outputs).

Disabling response storage does not guarantee zero retention. Provider abuse monitoring, image scanning and applicable retention policies still apply. Administrators must check the provider project's [data controls](https://developers.openai.com/api/docs/guides/your-data) before enabling. The private service does not persist screenshots, metadata, prompts, provider output or raw credentials in its SQLite review tables and does not log their contents. Service/operator infrastructure and the provider have their own policies.

Every operation requires a signed-in Roblox account capability and the active service access policy. Invitation-only deployments also require a valid private invitation. Ownership comes from the server account record. Authorization is rechecked after receiving the body, immediately before provider dispatch and after the provider reply. Missing/expired/revoked accounts, or invalid invitations in an invitation-only deployment, fail before new provider work. OAuth account removal forgets the local account, synchronously revokes its preference grants and aborts owned reviews before awaiting Roblox token revocation. This applies to sign-out, an acknowledged replacement and cancellation of a ready but unacknowledged login; a slow provider revoke cannot delay local cleanup or affect the retained account's grants. Cancellation IDs are scoped to the authenticated account; an acknowledgment does not reveal whether that raw ID exists for another account and cannot cancel its request. Neither the Roblox capability nor provider key enters the AI prompt or an export.

## Cost and configuration

All these Worker settings are mandatory for availability; otherwise the feature stays disabled:

| Setting                                                                                          | Meaning                                                                         |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| `VISION_ENABLED=1`                                                                               | Explicit enablement; omitted or `0` disables it.                                |
| `VISION_OPENAI_KEY`                                                                              | Server secret, never a browser/Figma setting.                                   |
| `VISION_MODEL`                                                                                   | Exact Responses model supporting image input and strict JSON output.            |
| `VISION_INPUT_MICROS_PER_MILLION` / `VISION_OUTPUT_MICROS_PER_MILLION`                           | Current USD price in microdollars per million tokens. Prices are not guessed.   |
| `VISION_IMAGE_TOKEN_BUDGET`                                                                      | Verified model-specific upper bound for one low-detail image: 85–32,768 tokens. |
| `VISION_INPUT_TOKEN_BUDGET`                                                                      | Whole input bound: 4,096–100,000 tokens.                                        |
| `VISION_OUTPUT_TOKENS`                                                                           | Provider output limit: 256–4,096 tokens.                                        |
| `VISION_DAILY_USER_COST_MICROS` / `VISION_DAILY_INVITE_COST_MICROS` / `VISION_DAILY_COST_MICROS` | Daily reservations, capped at USD10/USD50/USD100.                               |

These are operator settings. Use a restricted provider project and verify current model availability, prices and image-token bounds before enabling. Incorrect operator values cannot guarantee the real provider bill. Text input uses a conservative UTF-8-byte bound including instructions/schema, plus the configured image bound. Overflow fails before reservation. One request reserves at most USD1. Screenshots are at most 512 pixels per edge and 512 KiB; metadata contains at most 128 layers/24,000 UTF-8 bytes; provider responses are at most 64 KiB/24 suggestions.

SQLite atomically reserves worst-case configured input/output cost and one request against all scopes before outbound work. Limits are 10 requests per Roblox user/invitation partition, 50 per invitation, 200 total per day, and three simultaneous requests. Connections for the same user share their allowance. Rejection leaves no partial charge or attempt. Duplicate submitted IDs fail without another provider call. Failed, incomplete, timed-out and cancelled attempts retain their reservation because billing may already have occurred. The allowance is a conservative local reservation, not a provider invoice. Quotas reset at 00:00 UTC.

The 25-second provider deadline starts at admission, including alarm scheduling. **Cancel AI request** aborts browser work and requests server cancellation. Cancellation received before the review body is admitted leaves an opaque suppression record and consumes no provider quota or cost. An admitted request retains its reservation even if cancellation wins before provider dispatch. Changed/cancelled account, source or scope operations ignore late replies. Cancellation cannot retract data already received by the provider or guarantee zero billing. A new request needs explicit approval; an uncertain failure does not silently resend.

Only hashed attempt IDs, owning account/invitation/user hashes, state, expiry and integer quota amounts persist in review tables. Finished attempts and suppression records expire after 24 hours; pending leases after 30 seconds. Quota rows expire after the following daily window. Suppression records are bounded separately to 10 per user/invitation partition, 50 per invitation and 200 globally in a rolling 24-hour window. Repeated cancellation of the same ID and cancellation of an admitted request do not consume extra suppression capacity. Existing alarm/admission cleanup removes expired records; suppression survives a service restart. Cleanup/restart does not refund the active daily reservation.
