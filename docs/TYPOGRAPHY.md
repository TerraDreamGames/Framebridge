# Native text size conversion

Figma font size is an em size. Roblox TextSize specifies the height of a native line. Copying the same number makes supported native text smaller than the Figma capture; a captured text-shaped glow then reveals the displaced source silhouette.

Framebridge converts source em sizes using the selected built-in face's measured font metrics: (hhea ascent − descent + line gap) / unitsPerEm. It truncates the resulting line height and bounds it to 1–100 pixels, matching the actual Studio setter. A range notice explains property clamping. RichText size tags follow a separate positive-integer policy: native probes accept heights above 100, so large mixed, underlined and struck runs retain those sizes. Fractions are truncated before emitting tags because the native parser rejects fractional size strings. Text stays native, TextScaled stays false, and source identities remain unchanged.

These numbers come from the actual font files bundled with the tested macOS Studio installation. Alias names resolve through the existing destination mapping, including Source Sans 3 → SourceSansPro. Native GetFamilyInfoAsync confirms Arial → Arimo and GothamSSm → Montserrat; these common regular/bold engine aliases use their destination metrics and receive a font substitution notice. The complete face whitelist is intentionally bounded: unavailable remote faces and user-mapped asset families keep their source size, subject to native truncation/limits, with an unverified conversion notice. No font binary is redistributed.

Explicit Roblox TextSize and LineHeight properties retain their original values and units. A native FontFace override chooses the destination metrics and also applies to generated rich spans. Mixed source runs convert independently. A TextSize override scales their converted sizes in proportion to the first run before native limits; it now changes the visible spans instead of setting an inert base property. Explicit font themes remain raw Roblox units, with existing plain-text-only binding rules. When the first source run is italic and a later run is normal, generated rich text uses a neutral Normal label face: native font tags inherit the label’s italic style, so leaving the first run’s Italic base would also italicize later normal runs. Explicit `<i>` wrappers preserve the authored italic runs, and size conversion still uses each actual run face. An explicit native FontFace override remains authoritative on the base and every generated span.

Optional contextual text strokes normalize against the compiled native base TextSize before user size overrides. Roboto source size 20 emits native size 23, so a one-pixel source stroke uses Thickness 1/23 and stays one pixel at that base size; a native TextSize 46 override doubles it. Explicit stroke settings keep their native units. TextScaled previews use the resolved native size, with integer-fit quantization still visible.

An explicit Figma line height divides by the effective native text height; an underlined or struck single run uses its tagged height rather than the capped base property. Roblox's LineHeight range is 1–3; tighter or wider source leading receives a clamping notice. Native multiline probes show that spacing between differently sized rich lines uses each line's rendered height. One global multiplier cannot preserve fixed Figma leading for all such lines or wrapping. Mixed sizes with source leading receive an approximation notice; an explicit native LineHeight remains authoritative. Baseline placement, hinting, shaping, letter spacing, font version differences and multiline wrapping still require visual checks.

Contrast review converts verified native sizes back to em pixels before using large-text thresholds. For example, Roboto Bold source 17 emits native 19 and remains below the bold large-text threshold; Roboto source 24 emits 28 and is just below 24 em pixels after truncation. Unknown faces use the conservative 4.5:1 reference and disclose uncertainty. Mixed spans use their own effective face metrics and uncapped tagged heights. Contrast thresholds include inherited UIScale; TextScaled fit remains unverified and uses the conservative normal-text threshold. Constrained TextScaled minimums also convert from native heights to displayed em pixels; unknown minimum metrics receive an uncertainty notice. Small-text heuristics use verified em sizes with cumulative scale, while line-fit estimates retain native line heights.

The browser preview inverts verified native heights for CSS em sizes and uses native pixel line heights for leading. Its TextScaled fit remains approximate: the fit estimate converts to native units before applying UITextSizeConstraint limits, then converts back for CSS. Unknown face metrics keep approximate raw-size styling rather than a guessed multiplier. Browser font availability can still differ from Studio. The preview parses compiler-emitted RichText into typed runs and renders each family, weight, italic style, native size, color, transparency, underline and strike independently. Verified tagged heights convert back to em pixels without the base TextSize ceiling, and each run uses its native pixel leading. All runs share one inline text flow for wrapping and alignment. Label transparency composes with run transparency; literal source escapes decode once after tag recognition. TextScaled still uses a fit estimate, then scales tagged run sizes in proportion to the base native height, so rich fitting is approximate.

The browser parser supports font family/weight/size/color/transparency, bold, italic, underline, strike, line breaks and comments. It accepts only typed values and constructs React text/spans, without an HTML parser or injected source attributes. Malformed, unsupported or excessive markup remains literal with a tooltip instead of silently losing text; this includes manually authored stroke, highlight, caps and face tags. Custom font asset families fall back to the browser sans-serif face without fetching asset URLs. Native exports keep the complete original markup. During local simulation, rule-bound strings stay literal like the native runtime; no matching Text action restores the authored spans, and Stop test restores the complete authored text flow.
