# Editable live text shadows

Own normal text drop shadows retain the authored PNG correction while native text, font, size, color, opacity, rich text and local bounds agree with the captured baseline. The PNG stays above its native text in its original compositor. Once content or shaping changes, the runtime hides those stale pixels and draws shadows from the **current native glyphs**. Returning to the complete authored baseline restores the original capture. An opaque/partial native text background also switches to live paint because it changes the captured compositing assumptions. Text/font/shadow themes, live player bindings and Studio property edits use the same refresh path; shadow themes retain editable UIShadow parameters without rendering a rectangular box behind text.

The real TextLabel, TextButton or TextBox keeps its parent, input, position, size, foreground and background. Live paint lives in a sibling Folder, excluded from list/grid layout membership, with an exact ObjectValue reference to its owner. Its Frame follows rendered bounds instead of raw layout properties; native glyph layers mirror fonts, rich shaping, direction/OpenType settings, alignment, constraints, padding, UIScale, rotation and clipping. The host uses biased offset placement, a fractional anchor and exact float size constraints: positive scale geometry would feed back into automatic canvas measurement. A coalesced rendered-bounds correction aligns fractional scrolling without assuming device pixel density. Subpixel owners use a nonpositive position-scale residual when integer offsets cannot represent their fractional anchor, avoiding automatic-canvas growth. Degenerate zero sizing bases retain current paint with an explicit alignment notice. Corrected geometry is reused while the actual rendered bounds remain stable, preventing raw canvas float noise from undoing the alignment. Balanced padding shifts the glyph paint while its native bounds and clipping box remain fixed; local shadow offsets rotate with the owner. Helpers have source ownership but no layer identity, so independent component/repeat copies cannot accidentally claim each other's paint. They accept no input.

Each effect has one colored glyph fill. Three additional glyph labels have transparent fills and draw only contextual UIStroke contours. A single fill preserves hard-shadow rich-run opacity instead of compounding four coincident fills. Controlled inline stroke tags carry the current shadow RGB color and follow each rich font run's transparency, including fully transparent runs; color-only shadow theme edits also invalidate their cached paint. Authored stroke and mark/highlight paint remains on the real foreground only. Raw input or emitted helper markup beyond 65,536 bytes, input beyond 2,048 tags or 128 nested font scopes falls back to the current single glyph fill without contours and reports that bound. The contours approximate a soft edge; they do **not** reproduce Gaussian blur, negative spread or pixel-identical anti-aliasing. UIGradient alpha, custom contextual foreground strokes and stroke/highlight rich tags do not become an exact shadow mask. Native foreground styling remains editable. Inner shadows, effect blends and nontext captured silhouettes retain their existing approximation/capture limits.

Live glyph paint sits behind the entire editable text object. An opaque or partially opaque background on that object can cover its glow; the compiler reports this limitation and the runtime status identifies it. Use a transparent text child over a separate background Frame when internal glow matters. Generated screens use Sibling ZIndex behavior. An external Global collector needs an existing ZIndex gap above opaque ancestor backgrounds; the runtime preserves caller settings and cannot manufacture an intermediate integer paint layer without changing the user's hierarchy. These are rendering limits, rather than reasons to duplicate or hide the native foreground.

Refresh uses coalesced property/ancestry signals. It does not poll text/font state each frame. The Studio Edit watcher releases its controller on entering Play, and a generated controller claim replaces an older mount. Reparenting or detaching an owner removes its old outside-root paint; reattachment rebuilds it. Disposal after changed content never restores stale captured glyph pixels. Source-owned helper descendants can be removed by a compatible reimport, while custom children or scripts remain protected by the importer. Removing/rebuilding an owned paint host promotes application content to the real owner; deleting an already-destroyed owner uses a surviving ancestor or detaches retained content. Binding disposal restores authored text before final capture reconciliation.

The closed metadata carries visual data only: at most eight effects per owner, four glyph labels per effect, 4,096 glyph labels per mounted/exported selection, and a conservative 15,000 total-instance budget. The reservation includes four possible instances per glyph (label, stroke, text constraint and padding), five per paint host (Folder, Frame, exact owner reference, UIScale and size constraint), and generated runtime/world objects. The instance limit can therefore reject a selection before the glyph ceiling. Captured baselines are bounded to 8,192 UTF-8 bytes; larger content starts with live glyphs. Metadata is bounded to 65,536 bytes and cannot contain arbitrary scripts or fields.

JSON/relay validation, Studio staging/reimport, model export, all four source formats, repeats and reusable components carry the same visual metadata and trusted runtime. Browser preview switches from stale artwork to CSS shadows for current text/rich runs, including local simulation updates; CSS and native contour blur are approximate and are not pixel-equivalence claims.
