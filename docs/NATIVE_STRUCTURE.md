# Editable repeats, masks and native artwork structure

The bounded implementation now covers editable linear repeats, supported rectangular/circular CanvasGroup masks, separate container backgrounds, own normal content-shaped drop effects, and own paint blends over a known flat opaque parent. Text, functional children, layout and input remain native. Actual Figma pixels/persistence, uploaded artwork, device input/model insertion and the matching combined private release remain acceptance gates.

## Own drop effects and paint blends

Own normal **DROP_SHADOW** effects can become a separate **Drop effect artwork** ImageLabel on editable text, image/complex-fill containers and transparent containers. Filled-box shadows retain native UIShadow. Extraction replaces the eligible source UIShadow, so the effect is not drawn twice. A nontext live shadow theme uses the native filled-box fallback with an explicit notice. Native text shadow themes use [editable glyph paint](LIVE_TEXT_DECORATION.md), with a disabled UIShadow storing their editable parameters. Inner shadows, blur, effect/layer blend modes, native text/box strokes, Display P3 source colors, skewed/masked owners and unsupported effects keep an explicit approximation or intentional subtree image.

The controller works on temporary clones only. It freezes layout and dimensions, removes the owner's rotation from the artwork and renders two 8-bit sRGB PNGs into identical extended pixel bounds: with the own normal drops, then without only those drops. Descendant content, child opacity and child effects stay identical. Only the own effect is separated. Both exports must match measured bounds; cancellation or failure removes the scratch frame and discards unfinished cache entries.

Opaque source pixels omit completely hidden effect pixels. For containers, the PNG reconstructs **source OVER effect**, and sits below editable foreground and the separate fill image. Text needs a different compositor because Roblox draws children above their parent in sibling ZIndex mode. The text PNG reconstructs **effect OVER native text**, accounting for source opacity and the helper's own transparency. This correction matches captured glyph color/alpha. It remains in this compositor while the authored baseline matches; after live changes, [current glyph shadows](LIVE_TEXT_DECORATION.md) replace the stale capture in a separate layout-excluded underlay. See [Roblox's layering documentation](https://create.roblox.com/docs/ui/position-and-size).

Both paths check reconstructed premultiplied RGB and alpha with a maximum error of 3/255 per channel. Each pass and output are limited to 4,194,304 pixels, 4,096 pixels per edge and 20 MB per PNG; unsupported depth/color samples, corrupt or mismatched PNGs and pixels outside the reconstruction limit are rejected. The 3/255 bound compares the source PNG pair, not the appearance of a different native font, line wrapping, fill geometry or changed child state. Independent synthetic pixel tests verify both painter orders and text opacities 0, .25, .6 and 1. Fresh Figma and native artwork pixel comparison remains pending.

The helper follows local owner bounds, padding, scrolling, UIScale and native rotation without rewriting child geometry. The PNG itself remains captured artwork. Native text now switches to bounded current glyph paint when content/font/theme or geometry no longer matches its baseline. Nontext silhouettes and child-state changes remain frozen; resizing stretches that artwork and those paths still need a fresh source render or suitable native filled-box fallback. Controls/text remain editable and updates preserve their identities and user scripts. CanvasGroup applies group opacity once; the PNG and its native fill helper do not multiply that opacity again. A partially transparent nontext owner that remains a Frame, ImageButton or ScrollingFrame applies opacity independently to each helper. Its new drop effect therefore stays an explicit approximation instead of claiming group reconstruction; editable children and the existing background helper remain. An own paint blend combined with a drop effect also keeps an explicit unsupported-effect notice.

An extended helper cannot escape CanvasGroup's flattened texture bounds. Clipping ancestors can also trim it; place an outer glow in an unclipped surrounding container where that appearance is needed. Native QA observed the source `ClipsDescendants=false` property retained on CanvasGroup; that property readback does not prove that extended artwork escapes the texture. The compiler reports this limit, and verify clipped artwork in Studio. [CanvasGroup documentation](https://create.roblox.com/docs/reference/engine/classes/CanvasGroup).

A functional container's own non-normal paint stack can render against a source-derived, flat opaque parent RGB. Children, button input and layout stay native. This path accepts the supported Figma paint blend modes and stores the normalized backdrop in its asset metadata/cache signature. Changing that source parent color re-renders the own paint; child-only edits reuse it. The baked backdrop is frozen, so later parent changes in Studio need a fresh Figma render.

The parent must have one known opaque native solid fill, no rounding/effects/masks, and a supported normal layer mode. The child must remain inside that flat region; overlapping siblings and unbounded sibling appearance are rejected. Theme-owned, rule-owned, manually overridden or behavior-owned parent backgrounds, Display P3 documents, alpha/gradient/unknown backgrounds, layer-wide blends and unsupported modes retain an explicit approximation. Standalone vectors and subtree images are exported without an external parent backdrop and receive a clear notice; this path does not claim background-aware blending for those exports. Intentionally flatten the source backdrop with the artwork when that is required.

JSON/relay/import validation, all four source formats and model export preserve the same canonical `/effect` or `/decoration` helper, render mode, finite normalized bounds and optional backdrop. Helpers accept no input, theme or behavior, cannot contain authored children, and cannot receive image-preparation/slicing settings. Geometry reuses the trusted inspectable runtime at version 11; no arbitrary scripts or new property writers are introduced. General editing remains in native Explorer and Properties.

## Container backgrounds

A container with editable children, a layout, scrolling or button behavior keeps its native hierarchy even when its own fill needs an image. Supported normal-blend image fills, radial/transformed gradients, dense gradients and mixed unsupported fill stacks render into a separate **Background artwork** ImageLabel. Standalone vectors and artwork still become images. An explicit **Render as image** choice or `[raster]` still intentionally flattens the selected subtree.

Only the container's fills are rendered. The Figma controller hides children on a temporary clone, freezes auto-layout/Hug dimensions and excludes strokes/effects/opacity from that render. Source nodes remain unchanged. Separate fill/subtree cache entries avoid collisions, and child edits reuse the background render. Native borders/corners and supported filled-box shadows retain their normal conversion. Blur, inner shadows and unknown background blends report explicit approximations. The bounded normal drop-effect and known-flat paint paths below preserve decoration separately.

The helper sits outside list/grid/padding content and accepts no input or selection. Its normalized bounds follow the owner's viewport, including padding, inherited UIScale and scrolling. The trusted geometry runtime uses the native engine's different automatic/manual canvas bases to keep it fixed while content moves. Group opacity applies once. Resizing stretches the baked background; details inside that image remain pixels. The Figma explorer hides the owned helper, while the Images tab exposes its asset. Studio keeps it inspectable; retain the helper and its coordinate attribute when editing the native children.

JSON imports, all four source formats and model exports carry the same owned helper and optional geometry runtime, now version 11. Fill images use a distinct asset identity and their usual upload/manual-binding pipeline. Choose **Responsive layout** before analysis for native list/grid conversion; **Preserve geometry** retains measured child placement. Studio's import sizing choice is a separate setting.

## Linear repeats

Figma's linear `TRANSFORM_GROUP` repeats keep their native container and expand the original pattern into independent Roblox objects. Pixel and relative spacing, horizontal and vertical repeats, multiple children, stacked modifiers and nested groups are supported. A modifier repeats the whole preceding pattern; relative spacing uses that pattern's bounds. The repeat count includes the original.

Figma reports these children's relative transforms differently from ordinary frame/group children. The snapshot adapter derives the real group-local transform from the parent and child absolute transforms. Five actual Figma snapshots and their independently exported SVG renders are saved in `tests/fixtures/native-repeats.figma.json` and `native-repeats.svg.json`.

The Figma layer tree marks generated entries as **Copy**. Selecting a copy explains its origin and offers **Edit original**. Source edits apply to every copy; generated copies are not offered as separate property, class or interaction-target edits. Mixed selections containing copies offer **Select original layers** instead of controls whose edits would be ignored. After import, each copy is an ordinary editable Roblox instance.

Changing count or spacing in Figma and reimporting regenerates the pattern. Identities include repeat indices, so existing indices retain instances, listeners and custom scripts during compatible updates. Removed indices follow the normal importer removal behavior. Copies share image assets and prepared artwork, rather than adding uploads for identical images. Explicitly rendering the group as an image keeps one image and does not expand it.

Configured actions pointing inside a repeated pattern target the corresponding copied panel/control. State owners and motion slots follow their copied button; targets outside the pattern retain their original identity. Whole-pattern drawing and layout order remain distinct, including when copies overlap.

Radial/unknown modifiers or invalid repeat parameters use one image with a warning. Explicitly requesting editable UI for such a pattern produces a blocking diagnostic rather than claiming that its single original child represents every copy. Flattening an interaction still produces the normal blocking interaction diagnostic. Expansion is bounded to 10,000 total Roblox instances, including helpers; excessively long nested identities or unsupported dimensions are rejected with an actionable message.

The normal JSON import, Roblox model, React Lua, Fusion, roblox-ts JSX and vanilla Luau outputs all receive the expanded tree. Source format runtimes remain conditional on configured behavior.

## Editable masks

Unrotated rectangles with one uniform radius and circular ellipses become transparent `CanvasGroup` objects with `UICorner`. Following masked siblings become children of the clip. Exact layout rebases their transforms and direct artwork bounds to keep their authored positions. Responsive layout retains the original child geometry and constraints inside a noninteractive **Mask content coordinates** canvas. Existing source IDs and image identities stay intact. Reimporting a moved/resized Figma mask updates the crop without moving the content's authored coordinates, and matching native instances, listeners and custom scripts survive.

Uniform alpha masks use `GroupTransparency`, including translucent solid fills, stacked uniform fills and gradients with constant alpha. Vector masks use their filled outline at full opacity when any supported fill region has positive opacity; empty/zero-opacity masks reveal nothing. Mask colors are not imported as visible paint. Separate masks start separate runs. Earlier siblings stay outside, and a direct clipped frame/component or separate mask object ends the preceding scope following [Figma's mask documentation](https://help.figma.com/hc/en-us/articles/360040450253-Masks). A nested scrolling viewport inside an ordinary group stays inside the clip; the synthetic quest example retains `ScrollingFrame`, `UIListLayout`, editable labels and automatic canvas growth.

The layer inspector explains the change in hierarchy and the need to retain CanvasGroup. Children remain configurable through normal properties and export setup. The Figma explorer hides the generated coordinate frame and its UIScale so users edit the actual content. Those helpers remain inspectable in Studio; keep them intact. The browser preview clips the descendants and retains scrolling; overflow shorthand and longhands are kept separate so React does not clear a mask's clip on updates.

Non-circular ellipses, unequal radii, stroked masks, variable/unknown alpha, luminance masks, shape effects, transformed masks/ancestors and masks directly inside auto layout currently use a combined image with an explicit notice. Requesting native output for an unsupported mask, or assigning an incompatible class/render choice to the mask itself, produces a blocking diagnostic. Rendering the entire parent as an image remains an intentional option. Unsupported mask shapes retain the explicit combined-image fallback; this stage does not separate their decoration from the unsupported clip.

Responsive exports preserve the original parent's sizing region through the coordinate canvas. A trusted runtime follows that parent's rendered content bounds, including padding, scrolling canvas position and inherited UIScale, while the clip keeps its independent constraints. The runtime changes only the helper's geometry and compensating UIScale; edits to ordinary child Position and Size remain intact. It uses relative coordinates because Roblox truncates offset components, and caches unchanged geometry. The updated Studio plugin watches imported roots in Edit; the exported client runtime handles Play and all four source frameworks. Both require the matching version-11 runtime. Updating the source does not update an already installed private plugin.

All 25 pairs of min/max/center/scale/stretch constraints match ordinary unmasked content at four native canvas sizes. Native checks also cover independent crop edits, preserved user geometry, padding, zoom, scrolling source canvases, all three Studio import unit modes, editor watcher removal/cleanup and identity-preserving responsive reimport. These synthetic native measurements do not prove fresh Figma pixel/input fidelity. CanvasGroup also requires sibling ZIndex mode and consumes texture memory. SurfaceGui rejects CanvasGroup through the existing world-space validation; use an intentional image there until a supported native alternative exists.

Extract the original coordinate parent together with a responsive mask when creating a reusable component. Extracting a clip alone would omit its dependency and is rejected with a clear message.

## Automatic source canvases

New coordinate helpers use a ScrollingFrame with scrolling disabled, no scrollbar and no input/selection. This is an owned geometry helper, not a second user-facing scroll area. Roblox uses the viewport as the size-scale basis on both axes of an automatic canvas, while position scales use the viewport only on automatic axes and the padded canvas on other axes. The helper reproduces those independent bases without rewriting editable child Position/Size values. Ordinary parents and manual canvases use the same content region for both bases.

Three native regressions fail with the old Frame helper and pass with the new canvas helper. Tests compare actual masked content with an independent unmasked native reference for X, Y and XY, at two viewport sizes and three zoom factors, with mixed scale/offset padding, scrolling and independent crop edits. Four generated frameworks separately preserve user-authored mixed scale/offset properties under these conditions.

Legacy Frame helpers remain accepted and have verified ordinary-parent/manual-canvas compatibility. Re-export old automatic-canvas designs to receive the new helper; this stage does not migrate already imported legacy helpers. Both plugins and the generated version-11 runtime must come from the same build. No matching private release has been installed yet.
