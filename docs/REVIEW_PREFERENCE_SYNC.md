# Private review preference sync

Open **More options → Review structure** after analysis. **Naming and review hints** authors local export naming conventions and literal layer-name hints for known class, scrolling, layout or role choices. Source, PascalCase, camelCase and snake_case styles support an optional ASCII prefix. Hints contain at most 64 characters; there are at most 32. The existing 200 remembered corrections remain available. Suggestions require review and Apply; explicit layer settings win, unavailable classes are excluded, and children baked into artwork cannot receive separate corrections. Reset local review preferences clears corrections, hints and naming together. Accepted corrections use the normal configuration and Undo path.

Local storage remains the default. The optional **Private preference sync** pane requires sign-in through **Images → Roblox sign-in** in the hosted private build and a separate consent checkbox. Choose Personal or an authorized **Roblox group**. These scopes do not represent Figma teams. Connecting creates an empty cloud record or fetches the existing one; it does not upload local preferences or replace them.

- **Publish local choices** uploads the reviewed local preference collection.
- **Fetch cloud choices** retrieves the cloud version while retaining the local copy. **Use cloud copy locally** explicitly replaces local preferences, then suggestions still require review.
- A stale publish exposes a conflict and both inspectable copies. **Replace cloud with my local copy** explicitly retries against the displayed remote version. Another concurrent write can conflict again.
- **Reset cloud choices** has a separate confirmation. It clears cloud preferences while retaining local and peer copies.
- **Revoke this sync connection** removes this connection's access, retaining the cloud record and other connections. Roblox disconnect also removes its preference grants. An expired/revoked connection has a local **Forget this installation's sync access** recovery path.
- **Delete cloud preferences** requires a confirmation naming the Personal/Roblox-group scope. It removes the shared record and every grant to it. Other installations retain their local copies; their next cloud request fails and they can reconnect. No peer is silently reset.

Sync sends only the closed, versioned preference schema: known typed corrections, manually authored generic hints, naming settings and the enabled flag. Deliberately remembered layer names are included. Avoid confidential/project-specific text in remembered names or shared hints. Source IDs, design/export packages, screenshots, text contents, artwork, Roblox asset IDs, API keys, provider tokens and executable code are excluded. Unknown fields, malformed values and oversized collections fail validation rather than being retained. Account credentials and the separate sync grant stay in private connection storage; neither preferences nor grants are added to exports or document plugin data.

Production local preferences and sync access use separate Figma clientStorage keys. Development uses browser localStorage. Local preferences remain installation-wide; signing into another account does not erase them. Only an explicit cloud pull changes them. Sync access is bound to the exact service origin and signed-in Roblox user. Closing waits for controller storage writes; storage errors offer retry. Cancellation aborts network work and ignores late results for obsolete accounts/operations. A sent write may already have committed; fetch before retrying. Cancellation cannot retract an acknowledged local storage write.

## Authorization and version handling

The Cloudflare private beta Worker derives Personal ownership from the server's OAuth account user ID. Group scope requires a fresh Roblox `token/resources` check on every read, publish and deletion, using the existing authorized creator grant and asset-write OAuth scopes. Client account/team IDs, invitation IDs and arbitrary creator labels are not accepted as ownership. Revoking one's grant remains available after losing group permission. Every route also checks the OAuth account's private invitation. The profile key includes the invitation partition, scope kind and server-owned Roblox ID, so different invitations do not share records even for the same user or group.

A new consent creates a random 256-bit grant tied to the particular OAuth connection. SQLite stores only its hash, with bounded expiry. Requests require both the OAuth account capability and sync grant; a peer cannot reuse another account connection's grant. OAuth disconnect, expired accounts and revoked invitations invalidate access. The existing beta Durable Object supplies atomic SQLite transactions; no additional service or end-user Node installation is needed.

Each snapshot has a random generation and monotonic revision. Publish, reset and delete compare both against the last fetched snapshot in the same transaction. A conflict returns the current snapshot without changing data. Deleting and recreating a profile changes its generation, preventing an old revision from matching a new record. This is manual sharing; there is no continuous preference polling or automatic conflict merge.

## Bounds and retention

One existing private beta room allows 100 profiles total, 30 per invitation, 200 live grants total and 8 per OAuth connection. Each preference payload is at most 32 KiB. The service accepts at most 60 preference requests per OAuth connection per hour in addition to the existing beta request budget. Admission rejects full storage without evicting live records or leaving a partial empty record.

Profiles expire 180 days after their last publish/reset; grants expire after 90 days. Reads do not extend retention. The existing scheduled cleanup and subsequent connection admission remove expired records, inactive-invitation data and orphaned grants. An invitation revocation denies access immediately; physical cleanup occurs on that cleanup/connection path. Explicit cloud deletion physically removes the profile and every linked grant. Clearing an installation's local access retains cloud data until explicit deletion or expiry.
