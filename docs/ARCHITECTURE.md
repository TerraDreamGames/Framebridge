# Connected transfer architecture

Pairing creates reusable sender and receiver capabilities. `GET /v1/session` validates a saved capability and returns its role, expiration and pairing state without exposing the other role's token. Only an unpaired receiver can recover its still-valid pairing code. The receiver also learns the current imported revision so a reload does not repeat the import. Figma saves its capability in `framebridge-studio-connection-v1` using serialized clientStorage writes and validates the fixed backend origin before any request. Delayed restores and errors cannot replace or clear a newer pairing. Studio uses place/backend-scoped plugin settings for published places; PlaceId 0 stays in memory to avoid resuming into a different blank place. See [connection lifetime and storage](PRIVATE_BETA.md).

Figma web plugin → authenticated HTTPS relay → Roblox Open Cloud / Studio inbox. The service is invisible in the user workflow. Native frames and text are compiled as before; raster assets are uploaded as Image assets and their IDs are bound into a credential-free package before delivery.

The private beta requires a per-tester invitation for session creation. The Worker stores invitation and session-token hashes; revoking a tester invalidates their existing sessions. Studio keeps its invitation in memory, while Figma optionally remembers it locally for standalone image uploads.

Studio creates a receiver token and a one-use, ten-minute pairing code. Figma exchanges the code for a separate sender token. Roles cannot read each other's endpoints. Sessions expire after two hours; disconnect revokes both roles. Studio polls while paired, including when its widget is closed. Received designs wait for review by default; the persistent Auto-import preference enables the normal validation and undo path, and matching screens use update mode by default. Review mode reports a ready receipt without importing. During a play test, the receiver holds the specific package until editing resumes. Local replacement, manual completion, and disconnect consume or invalidate that queue. Revision numbers prevent repeated delivery; failed acknowledgments retry without repeating imports. Figma waits for a revision-specific receipt and distinguishes imported, review-ready, queued, failed, and superseded deliveries.

The API key, creator type, and creator ID persist in Figma `clientStorage` under `framebridge-cloud-settings-v1`, separately from conversion preferences and document overrides. They restore on plugin startup; **Clear key** removes the key from the stored record while preserving creator settings. Writes are serialized, and the UI acknowledges only the latest completed save. Load/save failures offer retry without echoing storage exception bodies. The browser development preview uses origin-local `localStorage`; packaged plugins use Figma storage. Storage is scoped to the plugin ID and device, not synchronized into the design or encrypted by Framebridge. See [Figma’s clientStorage documentation](https://developers.figma.com/docs/plugins/api/figma-clientStorage/).

During uploads the relay holds the key only for the current HTTP request. Figma supplies the same key on operation-status requests; it is never persisted by the Worker. The key is sent over HTTPS using a dedicated header, never URLs, document data or export packages. Only the fixed build-time relay origin is allowed. The service uses fixed Roblox API URLs and rejects redirects or invalid operation paths. Server failures never echo arbitrary upstream bodies. Deploy without body/header logging.

Create calls are never blindly retried after an ambiguous response. Pending/completed/failed jobs are deduplicated by credential, creator and PNG SHA-256 within the connection. Polls may retry transient failures. Image IDs are accepted only for returned Image assets, never Decal IDs. Pending moderation becomes an import warning. A failed or uncertain job is retained to avoid duplicate uploads. Operators must complete the live Image upload acceptance test before release.

The Cloudflare beta uses one bounded SQLite Durable Object for pairing, chunked packages, receipts, quotas and asset operation IDs. State survives restarts, and alarms clean expired sessions. Inbox and receipt requests wait up to 15 seconds for notification, responding immediately when their stored state changes. Notification listeners are disposable, limited to two per session/endpoint, and cleared on timeout, cancellation or disconnect. Stored revisions remain authoritative after a restart. Older clients retain five-second polling; updated Studio clients reconnect waiting requests after 0.1 seconds, with failure backoff up to 30 seconds. Queued imports and acknowledgment retries tick separately so waiting HTTP cannot delay finishing a Play-mode queue. The optional Node relay implements the same protocol with single-process in-memory state. See [private deployment and cost limits](PRIVATE_BETA.md).

Both plugins show the connection lifetime, with a warning in the final five minutes. Only the small countdown components rerender each second. Figma processes two PNG render jobs at a time, prioritizing required artwork, indexing source nodes once and avoiding a second compile for native-only designs. Existing PNG caching still reuses unchanged artwork for property edits. Image uploads use two concurrent jobs, commit each completed binding for recovery, check status immediately, and back off to longer intervals for slow Roblox operations. Cancellation stops new jobs and waits for started work to settle. Roblox processing and moderation remain outside Framebridge's control.

# Converter and importer internals

## Conversion pipeline

1. The Figma controller snapshots selected scene nodes into a plain, serializable `DesignNode` tree. Selected ancestors suppress redundant child roots. Limits are enforced before expensive work.
2. The pure compiler classifies supported native properties, required raster fallbacks, and approximations. No browser CSS is used to decide Roblox layout.
3. Image fallbacks use temporary Figma clones, with parent transforms removed and local transforms baked into the raster. The scratch frame encloses the rendered bounds, including effects. Its bounds are returned to the compiler so PNGs do not double-apply rotation, opacity, or cropping.
4. A second compilation includes rendered image bounds. The controller checks the source snapshot again to reject results if the design changed during the asynchronous work. Scratch nodes are removed in `finally`.
5. The UI sends compiled data and PNGs through the paired relay, or exports JSON/ZIP files as an offline fallback. Production bundles contain no external scripts, font requests or telemetry; network access is restricted to the configured relay origin.
6. Studio validates classes, property allowlists, enum families, IDs, bounds, depth, text lengths, and asset references. It constructs detached native instances before starting a change-history recording.
7. Fresh imports attach staged ScreenGuis. Updates reuse matching instances by source ID and layer ID. Property and parent changes are journaled and rolled back if a mutation fails.

## Identity and ownership

The source ID is stored in Figma document plugin data; layer IDs come from Figma. Generated helper objects get deterministic suffixes, such as `node-id/corner`. Studio stores `FramebridgeId`, `FramebridgeSource`, and the set of managed property names on generated instances.

Update mode only targets package root IDs directly under the destination. Screens from the same source that are not in the new selection are untouched. Duplicate matching imported identities cause an error rather than selecting one arbitrarily. A class change also blocks an update because replacing the object would break script references.

Updates preserve custom properties outside the managed property set. Removed generated properties reset to the staged instance's defaults. Existing custom children stay attached. Removed generated subtrees may be detached only if all descendants are also managed; otherwise the entire operation is rejected before changes. ChangeHistoryService records insertion, modification, and removal as one undoable operation.

## Responsive behavior

The Figma compiler supports measured geometry and responsive source constraints. Geometry mode uses pixel offsets; responsive mode sets native root containers to the viewport size, then encodes Figma constraints relative to the authored parent bounds. A `referenceSize` on each ScreenGui preserves the design canvas dimensions.

The Studio import preparation module adds a saved sizing configuration keyed by source identity. It defaults to Scale, converting each UDim2 component to `scale + offset / authoredParentSize` and zero offset. Pixel mode evaluates scale into authored offsets; Source preserves exported geometry. Parent bounds account for padding, grid cells and source aspect/size constraints. Native layouts retain control of child position; grid cell size and spacing also convert in Scale mode. Unknown/zero bounds retain source geometry with a notice. Legacy per-layer overrides remain compatible and can be cleared in the Import tab. Typography keeps its authored size; selection utilities can enable bounded TextScaled after import.

Editor.prepare clones the original delivery and adds or updates deterministic constraint helpers. The importer consumes this configured tree, while receiver identity/receipts retain the original package. Stored overrides are filtered by supported class/property/type and removed source IDs are dropped. Resetting edits restores the current source and removes Studio-generated constraints during the normal update path. The Studio configuration stays local; it does not rewrite the Figma document.

Safe auto layouts produce native list layout and padding modifiers. Other auto layouts keep measured child geometry, except explicitly absolute children that use their own constraints. The converter reports this boundary instead of silently inventing rules.

## Trust boundaries

Packages are input data, never Luau. Script classes, parent references, source code, URLs, and arbitrary property names are not accepted. Roblox image IDs remain strings to avoid loss of integer precision. The importer does not use `loadstring`, HTTP, `InsertService`, or remote code. The plugin transport uses HTTP only to retrieve data from its configured relay.

The package is validated by `Importer.decode` before calling `Importer.stage`. Callers of the lower-level stage function are responsible for providing a validated package. Studio passes explicit per-design script consent to staging; it defaults off and also governs automatic transfers. Without consent, behavior/theme metadata and generated game scripts are omitted. Visual geometry and update identities remain available to the Studio editor. Authored scripted features require opt-in for in-game operation; native buttons and panel roles alone do not require code.

Cleanup plans changes before recording them with ChangeHistoryService. Unused-data cleanup keeps update identities and attributes used by active visual features. Explicit detachment removes known metadata and untouched generated scripts, ending sync and scripted behavior. Unknown custom attributes and ordinary user scripts are preserved. An edited generated source or a custom descendant inside it protects its entire screen from cleanup. Failed changes restore attributes and script parents; successful removals remain undoable.

## Extending support

Add support to the normalized model and compiler, add class/property/value allowlists to the importer, and extend both the pure and native test suites. Features that cannot preserve geometry safely should retain a raster fallback or an explicit notice. Never silently drop unsupported styling or claim a measured similarity score without actually rendering and comparing both platforms.

## Studio React interface

View mounts upstream React Lua 17.2.1 through ReactRoblox.createRoot in a compact DockWidget. Import and UI tools are independent panels; hooks retain form drafts, tool scope and disclosure state. Components provides declarative fields, toggles, choices and collapsible sections. The plugin delegates layer navigation and ordinary property editing to native Studio windows.

During Play, a small connection panel shows status, expiry and a Disconnect action. Its Test instance never reads saved credentials, polls the relay or imports UI. Roblox's [PluginConnectionService](https://create.roblox.com/docs/reference/engine/classes/PluginConnectionService) carries bounded JSON status and a whitelisted Disconnect request to the original Edit controller, which clears queued delivery before revoking the connection. Older Studio versions without this API show a disabled panel directing users back to Edit. User plugins must be allowed to load during run modes in Studio Settings.

SelectionTools plans mutations against the current native selection, deduplicates selected subtrees and validates inputs before changing instances. Geometry conversion uses parent content bounds and inherited UIScale; layouts and automatic sizes retain ownership. Aspect, size and text constraints reuse existing instances. Anchor presets can preserve rendered position. Apply records one ChangeHistory operation and restores a mutation journal on failure. The controller subscribes to SelectionChanged and disconnects on unload. Selection utilities do not rewrite the incoming package or saved import settings.

The pinned production runtime is vendored as a compressed source/hierarchy tree. The build expands it into individual readable sources, preserving upstream names and require paths, then uses Rojo to export native Script, ModuleScript and Folder instances. The model and self-contained Rojo project ship together. Trusted game-runtime templates are split into source parts below Studio's source-assignment limit and reassembled as strings for imported game scripts. No custom loader, runtime decompression, loadstring or remote dependency require is used by the installation. A static factory adapter remains only in excluded test fixtures. React is a plugin-only dependency; imported game UI has no runtime framework dependency.
